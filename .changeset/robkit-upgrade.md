`pnpm robkit upgrade [version]` moves an install to a newer robkit: the newest on the registry, or the version given. The robkit the install has moves `create-robkit` in the catalog and installs it. The new robkit then raises the catalog's entry for each of robkit's other packages, replaces the lint policy in `tooling/eslint` and the Go module in `vendor/robkit/go`, adds or raises the other catalog entries it needs, raises `packageManager`, and installs. The first step asks the registry for no package but `create-robkit`, so a later robkit can drop or rename any other. It never changes your apps, the hub or admin, and prints create-robkit's changelog between the two versions, which says what to change by hand. It refuses, before it changes anything, without git or a commit, with a change not committed, while `pnpm dev` runs, for a version that isn't newer, and where a file it writes, a folder it replaces or a folder above one is a link. If `pnpm install` fails, or Ctrl+C stops it, it puts back every file it changed.
