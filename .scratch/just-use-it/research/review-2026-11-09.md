## The subdomain boundary

`SECURITY.md` treats sibling subdomains as a boundary. A browser treats them as same-site, so `SameSite=Lax` cookies travel between them and a sibling can set a cookie for the parent domain. These findings need attacker code on a sibling subdomain: an imported app, or XSS in any app.

- **A sibling app can act on another app as the viewer.** Verified. The guard never reads `Origin` or `Sec-Fetch-Site` (`packages/session/src/request-guard.ts:179-203`, `go/session/guarded.go:160-202`). A form on `evil.<domain>` can post to `notes.<domain>/api/...` with the viewer's cookie. The Go template's `POST /api/me` (`templates/stacks/go/server.go:81`) has no check on its path. Ticket 05.
- **A sibling app can frame admin.** Verified: nothing in the repo sets `frame-ancestors`, `X-Frame-Options`, `nosniff` or HSTS. Two tricked clicks in a framed admin open an app to everyone. Ticket 06.
- **A sibling app can shadow the session cookie.** Verified. The cookie is plain `robkit_session` (`packages/session/src/guard-http.ts:75-89`, `packages/core/src/routes/context.ts:56-71`). Core takes the first token that verifies, even one whose session is dead (`packages/core/src/session-store.ts:223-234`). The guard returns `expired` on the first expired token without looking for a live one (`packages/session/src/refresh-protocol.ts:176-184`, `go/session/refresh.go:162-180`). `robkit_state` can be planted the same way, which gives login CSRF at the callback. Ticket 03.
- **`/refresh` mints a token for any slug-shaped host on any port.** Verified. `packages/core/src/routes/session.ts:72-84` checks neither the catalog nor the port, and `onInstall` and `appOf` ignore the port (`packages/input/src/addresses.ts:71-85`). Ticket 02.
- **CORS trusts the hub and admin by hostname only.** Verified. `packages/core/src/app.ts:98-109` ignores scheme and port, and `app.db.test.ts:134` asserts `http://hub.robkit.test:3000` is allowed on a hosted install. Ticket 02.
- **The guard trusts `Host` and `X-Forwarded-Proto` for its own address.** `publicUrl` in `guard-http.ts:2-7` takes the protocol from the header. Behind the documented Cloudflare tunnel, Traefik may rewrite it to `http`, and core then refuses every `next` (unconfirmed, needs a real Coolify). The Express adapter reads `//evil.com/x` as another origin (`packages/express/src/guarded.ts:28`), Next builds its URL the same way (`packages/next/src/guarded.ts:20`), and an empty `Host` throws in Express and Next where Go answers 400. Ticket 01.
- **The state is never cleared.** `refresh-protocol.ts:97,149-152`, `go/session/refresh.go:85-92,128-130`. It stays valid for 10 minutes after the trip. Ticket 03.
- **A token needs no `exp`.** `packages/session/src/session-token.ts:97`, `go/session/token.go:126-130`. Core always sets one. Ticket 03.
- **A browser without fetch metadata loops between a gated app and the hub.** `refresh-protocol.ts:194-196` with the hub's `App.tsx:67-68`. Not taken; the PRD's out of scope says why and what the fix would be.

## Core

- **Access codes can be guessed online.** Verified. A generated code is 5 characters from 31, about 28.6 million, and a custom one may be 3 (`packages/core/src/access-codes.ts:15,26-27`). The limit is 10 failures per 15 minutes per exact address (`routes/session.ts:49-53`, `client.ts:29-37`), so rotating inside one IPv6 /64 gets a fresh limit each time. R chose to keep 5 characters and harden the limit. Ticket 04.
- **The limit's race is unbounded.** Verified. `retryAfter()` runs before `await signIn(...)` and `fail()` after it (`routes/session.ts:122-141,154-171`), so every request that arrives before the first verdict passes. Each password check is a 32 MB scrypt. Ticket 04.
- **The limiter's `prune` walks every client on every failure**, and its map has no cap (`rate-limit.ts:28-46`). Ticket 04.
- **Apps never leave the catalog.** `registerApps` only inserts or updates (`apps.ts:85-131`). A reused slug inherits the old rule. Ticket 24.
- **`GET /apps/:slug/access` needs no sign-in** (`routes/apps.ts:34-38`), so anyone can learn which slugs exist. The route's comment says it is deliberate. Recorded in ticket 02's comments as a known gap, not fixed.
- **A mixed-case `ROBKIT_DOMAIN` starts cleanly and then breaks.** Verified. `readDomain` keeps the case (`packages/input/src/env.ts:92,118-130`), and later comparisons are against lower-cased URL host names. Ticket 02.
- **Unexpected errors are logged whole** (`app.ts:80-86`). Unconfirmed whether Drizzle puts query parameters in its messages. Ticket 04 checks.
- **The session token is minted inside the sign-in transaction with a lazily loaded key** (`session-store.ts:104-108`, `app.ts:128-130`). Unconfirmed pool exhaustion right after a restart. Ticket 12 loads the key before serving.
- **Sessions can't be ended from outside the browser that holds them.** No "sign out everywhere", no pruning of dead rows. Out of scope here.

## create-robkit and dev

- **`npm create robkit` fails outside the checkout.** Verified. `packages/create-robkit/src/robkit-repo.ts:31` reads `pnpm-workspace.yaml`, the root `package.json`, `packages/*` and `tooling/eslint` from three folders up, and the package's `files` ships none of them. `packProblems` (`tooling/repo-checks/src/published.ts:95-108`) only checks that export and bin targets exist. Ticket 13.
- **Closing the terminal orphans every app.** Verified. `packages/dev/src/runner.ts:67-68` handles SIGINT and SIGTERM, not SIGHUP, and the apps are detached. Ticket 16.
- **The dev proxy listens on every interface.** Verified. `runner.ts:114` calls `proxy.listen(devPort)` with no host. Ticket 16.
- **Common setup failures print "robkit hit a bug".** Two `CommandProblem`s become an `AggregateError` (`runner.ts:104,137-146`, `failures.ts:29`, `run-command.ts:32`): Docker not running, port 3000 taken (`EADDRINUSE`, and only after every app started), native Windows (`spawn("pnpm")` ENOENT), a failed `turbo ls` (`robkit-command.ts:184-191`). Ticket 16.
- **A request hangs when the app dies mid-response** (`proxy.ts:70-73`). Ticket 16.
- **`robkit add` accepts an icon the manifest reader refuses** (`add-wizard.ts:70,147-153`). Then `pnpm dev`, `robkit check` and `robkit deploy` stop for the whole install. Ticket 15.
- **A failed init or add can't be re-run** (`write.ts:19-26`, `init.ts:30-33`, `robkit-command.ts:215-220`, `exec.ts:98`). Ticket 15.
- **Core is redeployed only in the run that creates an app** (`coolify-deploy.ts:187,206-225`). If core's deploy fails after the app's Coolify application exists, the re-run skips core and the app's role is never provisioned. An existing app that gains a `migrate` script doesn't redeploy core either. Ticket 22.
- **`robkit check` skips folders an app can import from**: `build`, `dist`, dot-folders and symlinked folders (`check.ts:126,196-205`). Ticket 23.
- **`robkit check` compares specifier text only** (`check.ts:58-68,101,244-272`). It misses a computed `import()` or `require`, `createRequire`, a pnpm alias, a `package.json` `imports` entry, tsconfig `paths`, absolute and `file:` specifiers, and a split cookie name. Ticket 23 refuses the computed forms and says in `SECURITY.md` that the rest stay open.
- **`robkit vendor` can strand itself**, and builds a shell string from the install path (`vendor.ts:121,138-142`). Ticket 13, since publishing retires vendoring for most installs.
- **Provisioning alters any existing role with the app's name** (`packages/dev/src/provision.ts:121-126`). Only `postgres` and `public` are reserved. Ticket 12.
- **Template overrides are read as UTF-8 text** (`generate.ts:55`), so a binary file in `robkit/templates/<stack>` is corrupted. Ticket 15.

## What held up

- Tokens: EdDSA is pinned, the audience is an exact match, and an app token carries no session id, so core never renews from one. "Can't check" (503) stays apart from "bad token" in both ports.
- CSRF on core: every POST must be `application/json`, and CORS allows only the hub and admin.
- `/refresh`'s `next` is parsed once and reused, takes a single-label slug only, and is https off localhost.
- The setup race is closed by a database constraint. scrypt has bounded parameters, `timingSafeEqual` and a dummy hash for unknown names.
- All SQL is parameterised, and migrations match `schema.ts`.
- Coolify calls time out, follow no redirects, and never log the token.
- Workflows use `pull_request` only, read-only tokens and no secrets.
