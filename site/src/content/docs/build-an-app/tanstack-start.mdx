An app on TanStack Start is a set of React routes that reach the server through server functions, run by Vite. `robkit add` writes a small working app: a table, a page that reads and writes it as the viewer, and a test. This guide walks through those files, then adds a table and a page of your own.

## Add the app

With `pnpm dev` running, in the install's folder:

```sh
pnpm robkit add notes --stack start
```

It asks who may open the app and which emoji the hub's launcher shows for it, then writes `apps/notes` and starts it at `http://notes.robkit.localhost:3000`. The folder's name is the app's slug. It names the subdomain, and the Postgres schema and role too.

## The routes

Each file in `src/routes/` is a route. `src/routes/index.tsx` is the page at `/`:

<TemplateFile path="stacks/start/src/routes/index.tsx" app="notes" />

This is how the page reaches its server:

- `shown` and `visit` are server functions. Their handlers run only on the server, where they read who is asking as `context.viewer` and hand it to a plain function in `src/visits.ts`.
- The loader calls `shown`. When the page first loads, it runs on the server, inside the page's request. After that, Start calls `shown` from the browser with a `GET` to the app's own server.
- The button calls `visit` through `useServerFn`. Start sends that call as a `POST` to the app's own server, so it passes the guard like any other request. A server function is a `GET` unless it says otherwise, so one that changes state says `method: "POST"`.

The guard refuses a write from another app's page, but it can't refuse a `GET`, which a link can send. So never change state in a `GET` server function or in a loader. The card itself is `HomeCard` in `src/home.tsx`, which uses the install's shared UI kit from `@internal/ui`.

## The server

`src/server.ts` puts the guard in front of Start's server:

<TemplateFile path="stacks/start/src/server.ts" app="notes" />

`guarded()` reads the app's slug and core's address from the settings `pnpm dev` sets, and asks core for the app's access rule. Anyone the rule leaves out never reaches a route or a server function. The `declare module` block tells Start's types that `context` holds the viewer. Start reads it only from this file, so keep it here.

`src/start.ts` sends each server function call through `sessionFetch` from `@robkit/react`:

<TemplateFile path="stacks/start/src/start.ts" app="notes" />

A call made once the session has lapsed goes through core's refresh and back, rather than failing. In production, `src/serve.ts` serves the built app with Node.

## The test

A server function runs only inside Start, so the test can't call one. It calls the plain functions in `src/visits.ts` with a viewer from `@robkit/start/testing`, and renders the card:

<TemplateFile path="stacks/start/src/home.test.tsx" app="notes" />

It covers neither the guard nor a server function's `method: "POST"`. Keep each handler down to one call to a plain function, as the example does, so the test covers the rest. Run it in the app's folder:

```sh app
pnpm test
```

## Make it yours

These steps give each viewer notes of their own: a table, its migration, the queries, a page with two server functions, and their tests.

### Add a table

Declare it in `src/schema.ts`, below the example's `visit`. The file already imports these names.

```ts title="apps/notes/src/schema.ts"
import { pgTable, serial, text, timestamp } from "drizzle-orm/pg-core";

/** One row per note, by the viewer who wrote it. */
export const note = pgTable("note", {
  id: serial().primaryKey(),
  author: text().notNull(),
  body: text().notNull(),
  at: timestamp({ withTimezone: true }).notNull().defaultNow(),
});
```

Then write its migration, in the app's folder:

```sh app
pnpm db:generate
```

It writes the next file in `drizzle/`. Commit it.

### Apply the migration

In the install's folder, while `pnpm dev` runs:

```sh
pnpm robkit migrate notes
```

The app keeps running, and the table is there for its next query.

### Add the queries

Add `src/notes.ts`, which follows `src/visits.ts`: the queries behind an interface, and plain functions that take a viewer.

```ts nocheck title="apps/notes/src/notes.ts"
import type { Viewer } from "@robkit/start";
import { desc, eq } from "drizzle-orm";
import { database } from "./database.ts";
import { note } from "./schema.ts";

/** A note, as the page shows it. */
export interface Note {
  id: number;
  body: string;
}

/** What the server functions store notes through. A test passes its own. */
export interface Notes {
  /** Adds a note by `author`. */
  add(author: string, body: string): Promise<void>;
  /** The notes `author` wrote, newest first. */
  list(author: string): Promise<Note[]>;
}

/** Notes in the app's database. */
export const notes: Notes = {
  async add(author, body) {
    await database().insert(note).values({ author, body });
  },
  async list(author) {
    return await database()
      .select({ id: note.id, body: note.body })
      .from(note)
      .where(eq(note.author, author))
      .orderBy(desc(note.at));
  },
};

// The page's server functions hand context.viewer to these plain
// functions, and a test calls them with a viewer it builds.

/** Whose notes these are: the viewer's id, or "nobody" in an open app. */
function authorOf(viewer: Viewer): string {
  return viewer.kind === "nobody" ? "nobody" : viewer.id;
}

/** The notes `viewer` wrote, newest first. */
export function notesOf(viewer: Viewer, notes: Notes): Promise<Note[]> {
  return notes.list(authorOf(viewer));
}

/** Adds a note by `viewer`, and returns their notes. */
export async function addNoteAs(
  viewer: Viewer,
  notes: Notes,
  body: string,
): Promise<Note[]> {
  if (body.trim() === "") {
    throw new Error(
      `The note ${JSON.stringify(body)} is empty, so it wasn't added.`,
    );
  }
  await notes.add(authorOf(viewer), body);
  return notesOf(viewer, notes);
}
```

Each note is keyed by the viewer's id, so one viewer never reads another's. In an app open to anyone, everyone not signed in shares the id `nobody`.

### Add the routes

Add `src/routes/notes.tsx`, the page at `/notes`. Its loader lists the viewer's notes with a `GET` server function, and its form adds one with a `POST` server function:

```tsx nocheck title="apps/notes/src/routes/notes.tsx"
import { Button } from "@internal/ui/components/ui/button";
import { createFileRoute } from "@tanstack/react-router";
import { createServerFn, useServerFn } from "@tanstack/react-start";
import { useState } from "react";
import { addNoteAs, notes, notesOf, type Note } from "../notes.ts";

/** The viewer's notes, newest first. A GET, so it records nothing. */
const listNotes = createServerFn({ method: "GET" }).handler(({ context }) =>
  notesOf(context.viewer, notes),
);

/** Adds a note by whoever is asking, and returns their notes. */
const addNote = createServerFn({ method: "POST" })
  .validator((body: unknown) => {
    if (typeof body !== "string") {
      throw new Error(`A note is text, and this one is a ${typeof body}.`);
    }
    return body;
  })
  .handler(({ context, data }) => addNoteAs(context.viewer, notes, data));

export const Route = createFileRoute("/notes")({
  loader: () => listNotes(),
  component: NotesPage,
});

function NotesPage() {
  const [shown, setShown] = useState<Note[]>(Route.useLoaderData());
  const [body, setBody] = useState("");
  const add = useServerFn(addNote);

  return (
    <main className="mx-auto grid max-w-sm gap-4 p-6">
      <form
        className="grid gap-2"
        onSubmit={(event) => {
          event.preventDefault();
          void add({ data: body }).then((list) => {
            setShown(list);
            setBody("");
          });
        }}
      >
        <label htmlFor="body">Note</label>
        <input
          id="body"
          required
          value={body}
          onChange={(event) => {
            setBody(event.target.value);
          }}
          className="rounded-md border px-3 py-2"
        />
        <Button type="submit">Add</Button>
      </form>
      <ul className="grid gap-1">
        {shown.map((each) => (
          <li key={each.id}>{each.body}</li>
        ))}
      </ul>
    </main>
  );
}
```

`validator` checks what the browser sent before the handler runs. A server function gets whatever body its caller sends, so it can't trust the type. Under `pnpm dev`, Start adds the route to `src/routeTree.gen.ts` as soon as you save the file.

### Test them

Add `src/notes.test.ts`. It keeps notes in a list, as the example's test keeps visits, and calls the plain functions as the owner and as a guest:

```ts nocheck title="apps/notes/src/notes.test.ts"
import { guest, owner } from "@robkit/start/testing";
import { describe, expect, it } from "vitest";
import { addNoteAs, notesOf, type Notes } from "./notes.ts";

/** Notes kept in a list, in place of the database. */
function notesInMemory(): Notes {
  const kept: { id: number; author: string; body: string }[] = [];
  return {
    add: (author, body) => {
      kept.unshift({ id: kept.length + 1, author, body });
      return Promise.resolve();
    },
    list: (author) =>
      Promise.resolve(
        kept
          .filter((each) => each.author === author)
          .map(({ id, body }) => ({ id, body })),
      ),
  };
}

describe("notes", () => {
  it("keeps each viewer's notes, newest first, from the others", async () => {
    const notes = notesInMemory();

    await addNoteAs(owner(), notes, "Buy milk");
    const shown = await addNoteAs(owner(), notes, "Call the vet");

    expect(shown.map((each) => each.body)).toEqual([
      "Call the vet",
      "Buy milk",
    ]);
    expect(await notesOf(guest({ roles: ["family"] }), notes)).toEqual([]);
  });

  it("refuses a note with no body", async () => {
    const notes = notesInMemory();

    await expect(addNoteAs(owner(), notes, " ")).rejects.toThrow(
      'The note " " is empty',
    );
    expect(await notesOf(owner(), notes)).toEqual([]);
  });
});
```

Run `pnpm test` in the app's folder again, and `pnpm lint` in the install's.
