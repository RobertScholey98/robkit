An app on Next.js uses Next's app router: server components read the viewer, and server actions change state. `robkit add` writes a small working app: a table, pages that read it as the viewer, an action that writes it, and a test. This guide walks through those files, then adds a table and a page of your own.

## Add the app

With `pnpm dev` running, in the install's folder:

```sh
pnpm robkit add notes --stack next
```

With `--stack` given, it asks nothing. It writes `apps/notes`, open to the owner alone and with the default icon, and starts it at `http://notes.robkit.localhost:3000`. Add `--access` and `--icon` to choose who may open it and its emoji, or leave out every option to be asked. [robkit add](/docs/reference/robkit-command/#robkit-add) lists each option, with `--roles` for an app some guests may open. The folder's name is the app's slug. It names the subdomain, and the Postgres schema and role too.

`src/app/visit-again.tsx` is a client component, so it can't call `viewer()`. It takes the count as a prop, and its form calls the action. Next sends an action as a `POST`, so the guard refuses one from another app's page. It can't refuse a `GET`, which a link can send, so never change state while a page renders or in a route handler's `GET`. `src/app/visits/page.tsx` is a second page, at `/visits`.

## The server

Next runs `src/proxy.ts` before each request, and the guard is the proxy:

<TemplateFile path="stacks/next/src/proxy.ts" app="notes" />

`guarded()` reads the app's slug and core's address from the settings `pnpm dev` sets, and asks core for the app's access rule. Anyone the rule leaves out never reaches a page, a route handler or an action. The proxy passes the viewer on in a request header, and `viewer()` reads it. `viewer()` throws on a request the proxy didn't guard, so keep the matcher covering every path but Next's own files under `/_next/`.

`next.config.ts` is one call to `withRobkit()` from `@robkit/next/config`:

<TemplateFile path="stacks/next/next.config.ts" app="notes" />

It puts the build in `dist`, lets the dev proxy's host reach Next's dev server, and turns Next's telemetry off unless you set `NEXT_TELEMETRY_DISABLED`. When `next dev` starts, it stops the app if a setting `pnpm dev` gives it, such as `ROBKIT_APP` or `ROBKIT_CORE_URL`, is missing or won't do, as when you run `next dev` on its own. Put your own Next settings in its argument, such as `withRobkit({ images: { ... } })`.

`pnpm dev` loads the app's `.env`. Next also loads `.env.local` and its other `.env` files itself, and `pnpm dev` neither loads nor blocks them. Keep your settings in `.env`, as [Settings](/docs/build-an-app/settings/) says. In production, `src/serve.ts` serves the built app with Node.

## Images

`<Image>` from `next/image` can't optimize a file in `public` unless the app is open to anyone. Files in `public` go through the guard, and Next's image optimizer fetches the file through your app's own server with no cookie. So in any other app the guard refuses it with a 401, and `<Image src="/logo.png">` shows a broken image. Either of these works:

- **Import the image**, as `import logo from "./logo.png"`, then draw it with `<Image src={logo} alt="..." />`. Next builds it into `/_next/static`, which the guard leaves out, and optimizes it.
- **Draw a file in `public`** with `<img src="/logo.png" alt="..." />`, or with `<Image src="/logo.png" unoptimized ... />`. The browser asks for it with the viewer's cookie, so the guard lets it through to whoever may open the app.

Leave the matcher in `src/proxy.ts` as it is. Letting the optimizer through would serve `public` to anyone.

## The test

`viewer()` reads the request's headers, which exist only while Next serves a request, so a test can't render `src/app/page.tsx`. It calls `Home` and `visitAgainAs` with a viewer from `@robkit/next/testing` instead:

It covers neither the guard nor the action. Keep each page and action down to reading the viewer and calling a plain function, as the example does, so the test covers the rest. Run it in the app's folder:

```sh app
pnpm test
```

## Make it yours

These steps give each viewer notes of their own: a table, its migration, the queries, a page with an action, and their tests.

### Add a table

Declare it in `src/schema.ts`, below the example's `visit`. The file already imports these names.

```ts title="apps/notes/src/schema.ts"
import { pgTable, serial, text, timestamp } from "drizzle-orm/pg-core";

/** One row per note, by the viewer who wrote it. */
export const note = pgTable("note", {
  id: serial().primaryKey(),
  author: text().notNull(),
  body: text().notNull(),
  at: timestamp({ withTimezone: true }).notNull().defaultNow(),
});
```

Then write its migration, in the app's folder:

```sh app
pnpm db:generate
```

It writes the next file in `drizzle/`. Commit it.

### Apply the migration

In the install's folder, while `pnpm dev` runs:

```sh
pnpm robkit migrate notes
```

The app keeps running, and the table is there for its next query.

### Add the queries

Add `src/notes.ts`, which follows `src/visits.ts`: the queries behind an interface, and plain functions that take a viewer.

```ts nocheck title="apps/notes/src/notes.ts"
import type { Viewer } from "@robkit/next";
import { desc, eq } from "drizzle-orm";
import { database } from "./database.ts";
import { note } from "./schema.ts";
import { visitorId } from "./visits.ts";

/** A note, as the page shows it. */
export interface Note {
  id: number;
  body: string;
}

/** What the page and its action store notes through. A test passes its own. */
export interface Notes {
  /** Adds a note by `author`. */
  add(author: string, body: string): Promise<void>;
  /** The notes `author` wrote, newest first. */
  list(author: string): Promise<Note[]>;
}

/** Notes in the app's database. */
export const notes: Notes = {
  async add(author, body) {
    await database().insert(note).values({ author, body });
  },
  async list(author) {
    return await database()
      .select({ id: note.id, body: note.body })
      .from(note)
      .where(eq(note.author, author))
      .orderBy(desc(note.at));
  },
};

// The page and its action hand viewer() to these plain functions, and a
// test calls them with a viewer it builds.

/** The notes `viewer` wrote, newest first. */
export function notesOf(viewer: Viewer, notes: Notes): Promise<Note[]> {
  return notes.list(visitorId(viewer));
}

/** Adds a note by `viewer`, and returns their notes. */
export async function addNoteAs(
  viewer: Viewer,
  notes: Notes,
  body: string,
): Promise<Note[]> {
  if (body.trim() === "") {
    throw new Error(
      `The note ${JSON.stringify(body)} is empty, so it wasn't added.`,
    );
  }
  await notes.add(visitorId(viewer), body);
  return notesOf(viewer, notes);
}
```

Each note is keyed by the viewer's id, so one viewer never reads another's. In an app open to anyone, everyone not signed in shares the id `nobody`.

### Add the routes

Add `src/app/notes/actions.ts`, a server action that adds a note from a form:

```ts nocheck title="apps/notes/src/app/notes/actions.ts"
"use server";

import { viewer } from "@robkit/next";
import { revalidatePath } from "next/cache";
import { addNoteAs, notes } from "../../notes.ts";

/** Adds a note from the form's body field, by whoever is asking. */
export async function addNote(form: FormData): Promise<void> {
  const body = form.get("body");
  if (typeof body !== "string") {
    throw new Error(
      `The form sent body as ${body === null ? "nothing" : "a file"}, not text.`,
    );
  }
  await addNoteAs(await viewer(), notes, body);
  revalidatePath("/notes");
}
```

`revalidatePath` tells Next to render `/notes` again, so the new note shows. Then add `src/app/notes/page.tsx`, the page at `/notes`, which lists the viewer's notes and posts its form to the action:

```tsx nocheck title="apps/notes/src/app/notes/page.tsx"
import { Button } from "@internal/ui/components/ui/button";
import { viewer } from "@robkit/next";
import { notes, notesOf } from "../../notes.ts";
import { addNote } from "./actions.ts";

/** The viewer's notes, newest first, and a form that adds one. */
export default async function Notes() {
  const shown = await notesOf(await viewer(), notes);

  return (
    <div className="grid w-full max-w-sm gap-4">
      <form action={addNote} className="grid gap-2">
        <label htmlFor="body">Note</label>
        <input
          id="body"
          name="body"
          required
          className="rounded-md border px-3 py-2"
        />
        <Button type="submit">Add</Button>
      </form>
      <ul className="grid gap-1">
        {shown.map((each) => (
          <li key={each.id}>{each.body}</li>
        ))}
      </ul>
    </div>
  );
}
```

### Test them

Add `src/notes.test.ts`. It keeps notes in a list, as the example's test keeps visits, and calls the plain functions as the owner and as a guest:

```ts nocheck title="apps/notes/src/notes.test.ts"
import { guest, owner } from "@robkit/next/testing";
import { describe, expect, it } from "vitest";
import { addNoteAs, notesOf, type Notes } from "./notes.ts";

/** Notes kept in a list, in place of the database. */
function notesInMemory(): Notes {
  const kept: { id: number; author: string; body: string }[] = [];
  return {
    add: (author, body) => {
      kept.unshift({ id: kept.length + 1, author, body });
      return Promise.resolve();
    },
    list: (author) =>
      Promise.resolve(
        kept
          .filter((each) => each.author === author)
          .map(({ id, body }) => ({ id, body })),
      ),
  };
}

describe("notes", () => {
  it("keeps each viewer's notes, newest first, from the others", async () => {
    const notes = notesInMemory();

    await addNoteAs(owner(), notes, "Buy milk");
    const shown = await addNoteAs(owner(), notes, "Call the vet");

    expect(shown.map((each) => each.body)).toEqual([
      "Call the vet",
      "Buy milk",
    ]);
    expect(await notesOf(guest({ roles: ["family"] }), notes)).toEqual([]);
  });

  it("refuses a note with no body", async () => {
    const notes = notesInMemory();

    await expect(addNoteAs(owner(), notes, " ")).rejects.toThrow(
      'The note " " is empty',
    );
    expect(await notesOf(owner(), notes)).toEqual([]);
  });
});
```

Run `pnpm test` in the app's folder again, and `pnpm lint` in the install's.
