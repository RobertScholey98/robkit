# @internal/repo-checks

Checks on the repo as a whole, run as Vitest tests, and the scripts CI runs on a pull request. `pnpm check` and `pnpm check:all` both run the tests. Turbo builds the published packages first, because some checks read their `dist`.

Run them, or one. Run `pnpm turbo run build` first if the packages' `dist` is missing or stale, since running one test skips turbo:

```sh
pnpm --filter @internal/repo-checks test
pnpm --filter @internal/repo-checks exec vitest run src/glossary.test.ts
```

Each check's failure names the file and says what to change. The tables below say more, and where an exception goes when the check is wrong for one case.

## The scripts CI runs

These run in CI's jobs, not in `pnpm check`. Each has a test that runs it.

| Script                         | Where it runs                                                            | Fails on                                                                                                                      | How to fix it                                                                                                                                                              |
| ------------------------------ | ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `check-commit-subjects.ts`     | The commit-msg hook, and CI on every commit of a pull request but merges | A subject over 72 characters, ending in a period, starting with a lowercase letter, or whose first word ends in "ed" or "ing" | Reword it: `git commit --amend` for the last commit, or an interactive rebase for older ones.                                                                              |
| `check-coverage-thresholds.ts` | CI, on a pull request, against its base                                  | A coverage threshold lower than on the base, or a package's `vitest.config` deleted while the package stays                   | Don't lower thresholds. Add tests instead.                                                                                                                                 |
| `check-coverage-ratchet.ts`    | CI, after `pnpm check:all`                                               | A threshold more than 2 points under what CI just measured, or a package with thresholds and no coverage report               | Raise the threshold to the number the message names. Set it from CI's measurement, not your machine's.                                                                     |
| `check-pr-ticket.ts`           | CI, on a pull request not opened by a bot                                | A pull request body whose `## Ticket` section names no file under `.scratch/`, or one that doesn't exist on the branch        | Name the ticket's file. Without a ticket, add one with `**Status:** needs-triage` in the same pull request; see [CONTRIBUTING.md](../../CONTRIBUTING.md#without-a-ticket). |
| `print-test-times.ts`          | CI, after `pnpm check:all`                                               | No turbo run summary to read                                                                                                  | Run turbo with `TURBO_RUN_SUMMARY=true`, as CI does. It writes each test task's time to the job summary and the log.                                                       |

## Add a check

1. Write the check as a function in `src/<name>.ts` that returns its problems as strings, each naming the file and what to change.
2. Test the function in `src/<name>.test.ts` with input it passes and input it fails, then add a test that runs it on the repo itself and expects no problems.
3. If it reads a file outside `packages/` and `tooling/`, add that file to the `inputs` of `@internal/repo-checks#test` and `#test:unit` in `turbo.json`, or turbo will serve a cached pass after it changes.
4. If it allows exceptions, keep them in one exported list with a reason for each, and fail on one that no longer applies.
5. Add a row to the table above.

A script for CI goes in `src/check-<name>.ts` or `src/print-<name>.ts`, with a test that spawns it.
