# @internal/repo-checks

Checks on the repo as a whole, run as Vitest tests, and the scripts CI runs on a pull request. `pnpm check` and `pnpm check:all` both run the tests. Turbo builds the published packages first, because some checks read their `dist`.

Run them, or one. Run `pnpm turbo run build` first if the packages' `dist` is missing or stale, since running one test skips turbo:

```sh
pnpm --filter @internal/repo-checks test
pnpm --filter @internal/repo-checks exec vitest run src/glossary.test.ts
```

Each check's failure names the file and says what to change. The tables below say more, and where an exception goes when the check is wrong for one case.

## Add a check

1. Write the check as a function in `src/<name>.ts` that returns its problems as strings, each naming the file and what to change.
2. Test the function in `src/<name>.test.ts` with input it passes and input it fails, then add a test that runs it on the repo itself and expects no problems.
3. If it reads a file outside `packages/` and `tooling/`, add that file to the `inputs` of `@internal/repo-checks#test` and `#test:unit` in `turbo.json`, or turbo will serve a cached pass after it changes.
4. If it allows exceptions, keep them in one exported list with a reason for each, and fail on one that no longer applies.
5. Add a row to the table above.

A script for CI goes in `src/check-<name>.ts` or `src/print-<name>.ts`, with a test that spawns it.

## Make a package

`pnpm new:package <name>` runs `src/new-package.ts`. It makes `packages/<name>` as `@robkit/<name>`, with the files, scripts and coverage thresholds the checks above ask of a published package, and adds it to `tooling/eslint/package-graph.js` and to this package's dependencies. It refuses a name that isn't a lowercase slug, or a package that exists. `new-package.test.ts` makes one and runs the checks on it.
